02 / TRANSACTION PIPELINE

Enam gerbang sebelum outcome diterima.

Pilih tahapan untuk melihat kontrak operasionalnya.

Klasifikasi ReadOnly, Writable, WritableButUnsafe, UnknownSemantic, VerifiedConstraints, dan IncompleteMetadata. Hak tulis file saja tidak cukup untuk memperoleh izin mutasi.
11 workload states, diagnosis PSI CPU/memory/I/O, thermal headroom dan trend. Objective meliputi InteractiveLatency, ThroughputBalance, MemoryRelief, IoLatencyRelief, ThermalStabilization, Recovery, dan EmergencyMitigation.
Strategi thermal relief menggunakan kandidat yang telah lolos validasi, termasuk schedutil damped pacing dan I/O burst pacing. Hysteresis mengatur recovery; emergency memprioritaskan rollback.
CentralMutationCoordinator memastikan satu transaksi aktif per domain dan mendahulukan EmergencySafety > ThermalStabilization > PressureGuard > WorkloadOptimization > BackgroundEfficiency.
CFJ4 write-ahead journal disimpan sebelum write. Baseline, boot identity, dev:ino, O_NOFOLLOW/fstat, dependency ordering, dan immediate readback membatasi risiko perubahan.
Outcome dinilai sesudah settling terhadap domain-specific noise floor. Verdict dapat retain, rollback, inconclusive, atau ownership lost. CFTS2 menyimpan adaptive scale, cooldown, dan capability fingerprint.
03 / CONTROL DOMAINS

Pengendali yang saling berkoordinasi.

CPU Policy / UClamp

CPUFreq policy dan governor-aware pacing; cgroup semantic discovery serta konversi encoding UClamp 0..1024 versus persen.

Thermal Core

Thermal zone, hwmon, Android severity, OEM trip points, sensor validity, serta pemulihan dengan hysteresis.

Block I/O / VM Memory

PSI contention evidence dan bounded policies. Node dengan semantik tidak dikenal atau unsafe tidak boleh ditulis.

GPU / Vulkan

GPU devfreq capability discovery dan Vulkan implicit pass-through layer tanpa mengarang extension atau fitur hardware.

Power Longevity

Bounded battery step-charging ceiling reduction dan cgroup v2 relative I/O weighting jika didukung.

Power HAL / Predictor

Nonblocking AIDL capability discovery. Hybrid ONNX (opsional) dengan fallback online predictor; prediksi bukan jaminan performa.

04 / CONFIGURATION CONTRACT

Pengaturan dan provenance.

Konfigurasi persisten berada di /data/adb/coreflow/coreflow.conf; fallback paket di /system/etc/coreflow/default.conf. Nilai harus melewati validasi dan batas runtime.

enable_uclamp

Master gate untuk transaksi top-app UClamp.

top_app_interactive_min / top_app_interactive_max

Floor dan ceiling internal capacity 0..1024; representasi kernel ditentukan melalui discovery.

ui_adaptive_bias

Intent bias: battery, balanced, atau responsiveness.

temp_monitor_interval_ms

Interval pengambilan sampel termal dibatasi 1000..60000 ms.

thermal_trip_celsius / thermal_recover_celsius

Preview/fallback trip dan recovery hysteresis; produksi memprioritaskan Android severity dan OEM zone trips.

emergency_rollback_on_overheat

Gerbang rollback baseline ketika terjadi panas ekstrem.

cpu_pressure_boost_pct

CPU PSI avg10 threshold untuk sustained load.

memory_pressure_guard_pct / io_pressure_guard_pct

PSI avg10 thresholds untuk PressureGuard.

Tidak ada parameter yang cocok.

05 / OPERATIONAL COMMANDS

Inspect, stop, recover.

Jalankan sebagai root pada perangkat yang telah memasang modul. Perintah rollback adalah tindakan mutatif dan perlu digunakan secara sadar.

su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --status'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --capabilities'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --stop'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --rollback-baseline'
Jangan hapus /data/adb/coreflow/baseline.journal secara manual untuk melewati pemeriksaan recovery. Kill switch: /data/adb/coreflow/DISABLE atau disable modul lewat root manager.

07 / SAFETY INVARIANTS

Otoritas melalui bukti, bukan pemaksaan.

OEM baseline adalah referensi, bukan batas kemampuan optimasi. Namun CoreFlow harus membuktikan semantik, keamanan, ownership, dan outcome sebelum mempertahankan perubahan.

No verified constraints → no write. No valid journal → no mutation. No readback → no success. Ownership lost → no overwrite. No measurable improvement above noise floor → no unverified retention.

Setiap kapabilitas dapat berbeda menurut kernel, vendor, root environment, dan build. Dokumentasi ini menjelaskan kontrak desain yang dinyatakan repository; bukan sertifikasi bahwa semua jalur berhasil pada semua perangkat.
