02 / TRANSACTION PIPELINE

Enam gerbang sebelum outcome diterima.

Pilih tahapan untuk melihat kontrak operasionalnya.

Klasifikasi ReadOnly, Writable, WritableButUnsafe, UnknownSemantic, VerifiedConstraints, dan IncompleteMetadata. Hak tulis file saja tidak cukup untuk memperoleh izin mutasi.
11 workload states, diagnosis PSI CPU/memory/I/O, thermal headroom dan trend. Objective meliputi InteractiveLatency, ThroughputBalance, MemoryRelief, IoLatencyRelief, ThermalStabilization, Recovery, dan EmergencyMitigation.
Strategi thermal relief menggunakan kandidat yang telah lolos validasi, termasuk schedutil damped pacing dan I/O burst pacing. Hysteresis mengatur recovery; emergency memprioritaskan rollback.
CentralMutationCoordinator memastikan satu transaksi aktif per domain dan mendahulukan EmergencySafety > ThermalStabilization > PressureGuard > WorkloadOptimization > BackgroundEfficiency.
CFJ4 write-ahead journal disimpan sebelum write. Baseline, boot identity, dev:ino, O_NOFOLLOW/fstat, dependency ordering, dan immediate readback membatasi risiko perubahan.
Outcome dinilai sesudah settling terhadap domain-specific noise floor. Verdict dapat retain, rollback, inconclusive, atau ownership lost. CFTS2 menyimpan adaptive scale, cooldown, dan capability fingerprint.
03 / CONTROL DOMAINS

Pengendali yang saling berkoordinasi.

CPU Policy / UClamp

CPUFreq policy dan governor-aware pacing; cgroup semantic discovery serta konversi encoding UClamp 0..1024 versus persen.

Thermal Core

Thermal zone, hwmon, Android severity, OEM trip points, sensor validity, serta pemulihan dengan hysteresis.

Block I/O / VM Memory

PSI contention evidence dan bounded policies. Node dengan semantik tidak dikenal atau unsafe tidak boleh ditulis.

GPU / Vulkan

GPU devfreq capability discovery dan Vulkan implicit pass-through layer tanpa mengarang extension atau fitur hardware.

Power Longevity

Bounded battery step-charging ceiling reduction dan cgroup v2 relative I/O weighting jika didukung.

Power HAL / Predictor

Nonblocking AIDL capability discovery. Hybrid ONNX (opsional) dengan fallback online predictor; prediksi bukan jaminan performa.

Native Input / Foreground Render Threads

Evdev touchscreen source menggunakan ioctl capability filtering, inotify hotplug, dan epoll. ForegroundTaskResolver membaca top-app PID dan whitelist TID render-critical sebelum cgroup v2 thread migration. Implementasi ini berada pada PR #29 yang masih Draft; device-level qualification belum selesai.

04 / CONFIGURATION CONTRACT

Pengaturan dan provenance.

Konfigurasi persisten berada di /data/adb/coreflow/coreflow.conf; fallback paket di /system/etc/coreflow/default.conf. Nilai harus melewati validasi dan batas runtime.

enable_uclamp

Master gate untuk transaksi top-app UClamp.

top_app_interactive_min / top_app_interactive_max

Floor dan ceiling internal capacity 0..1024; representasi kernel ditentukan melalui discovery.

ui_adaptive_bias

Intent bias: battery, balanced, atau responsiveness.

temp_monitor_interval_ms

Interval pengambilan sampel termal dibatasi 1000..60000 ms.

thermal_trip_celsius / thermal_recover_celsius

Preview/fallback trip dan recovery hysteresis; produksi memprioritaskan Android severity dan OEM zone trips.

emergency_rollback_on_overheat

Gerbang rollback baseline ketika terjadi panas ekstrem.

cpu_pressure_boost_pct

CPU PSI avg10 threshold untuk sustained load.

memory_pressure_guard_pct / io_pressure_guard_pct

PSI avg10 thresholds untuk PressureGuard.

Tidak ada parameter yang cocok.

05 / OPERATIONAL COMMANDS

Inspect, stop, recover.

Jalankan sebagai root pada perangkat yang telah memasang modul. Perintah rollback adalah tindakan mutatif dan perlu digunakan secara sadar.

su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --status'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --capabilities'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --stop'
su -c '/data/adb/modules/cfae_framework/system/bin/coreflowd --rollback-baseline'
Jangan hapus /data/adb/coreflow/baseline.journal secara manual untuk melewati pemeriksaan recovery. Kill switch: /data/adb/coreflow/DISABLE atau disable modul lewat root manager.
06 / MODULE LIFECYCLE

Dari boot hingga recovery.

Installation & read-only preflight

module/customize.sh memvalidasi ARM64 ELF/API, root-manager environment, identitas build, layout paket, SELinux state, CPUFreq, cgroup/UClamp, devfreq/KGSL, thermal zone, PSI, dan node evdev yang terlihat. Bila tersedia, script menjalankan coreflowd --capabilities dalam mode ReadOnly. Laporan disimpan di /data/adb/coreflow/install-preflight.log. Installer tidak menulis sysfs, cgroup, boot property, atau mengubah SELinux.

Early boot

module/post-fs-data.sh menangani konfigurasi awal dan persiapan lingkungan sebelum daemon.

Service

module/service.sh menjalankan lifecycle layanan; daemon menjaga singleton dan signal handling.

Uninstall / recovery

module/uninstall.sh merupakan jalur teardown modul; baseline rollback tetap wajib menghormati ownership dan journal integrity.

07 / SAFETY INVARIANTS

Otoritas melalui bukti, bukan pemaksaan.

OEM baseline adalah referensi, bukan batas kemampuan optimasi. Namun CoreFlow harus membuktikan semantik, keamanan, ownership, dan outcome sebelum mempertahankan perubahan.

No verified constraints → no write. No valid journal → no mutation. No readback → no success. Ownership lost → no overwrite. No measurable improvement above noise floor → no unverified retention.

Setiap kapabilitas dapat berbeda menurut kernel, vendor, root environment, dan build. Dokumentasi ini menjelaskan kontrak desain yang dinyatakan repository; bukan sertifikasi bahwa semua jalur berhasil pada semua perangkat.

09 / ENGINEERING EVOLUTION · PR #7 → PR #29

Dari mutation hardening menuju capability-driven actuators.

Sejarah berikut merangkum milestone refactor yang merged dan memisahkan pekerjaan yang masih Draft. Nomor PR menunjukkan urutan review GitHub, bukan klaim bahwa semua fitur dirilis atau aktif pada setiap perangkat.

PR #7 — Mutation ownership, recovery & CI foundation · MERGED

Menghapus eksperimen mutasi boot-property OEM, memperkuat ownership, crash recovery, dan reliabilitas CI. Ini menjadi baseline keselamatan untuk refactor berikutnya.

PR #9 — CoreFlow Device Validation Suite · MERGED

Menambahkan kontrak laporan CF-DVS berversi, validator offline, collector Android native bersesi, serta alur ekspor bukti perangkat. CF-DVS membedakan validasi source/CI dari penerimaan fisik di perangkat.

PR #11–13 — Dynamic Device Profiling & Feature Accountability · MERGED

CDDP memperkenalkan DeviceProfiler read-only, CPU policy topology, GPU/thermal/memory/cgroup inventory, dan baseline profil yang tidak dimutasi. Feature accountability menghapus synthetic 120 FPS serta menandai SurfaceFlinger, SkiaVK/VRS, Power HAL actuation, dan jalur lain yang belum tersedia secara jujur.

PR #14–15 — CLI lifecycle & discovery hardening · MERGED

Memperbaiki teardown perintah satu-shot --status/--capabilities, parser CPU policy, dan bounded ownership-contention recovery. Kegagalan discovery tidak boleh berubah menjadi tebakan parameter.

PR #16–19 — P2 lifecycle, platform context & tiered policy · MERGED

CoreFlowContext menjadi composition root dengan dependency injection dan reverse-order teardown; platform identity serta telemetry diberi confidence; workload classifier/CPU OPP planner mendapat admission policy; generic Linux provider dan HAL ownership quarantine memperluas dukungan tanpa mengendurkan bukti.

PR #20 — P3 semantic infrastructure · MERGED

Memperkenalkan discovery adapter root-injectable, tiga relasi bukti topology/driver ABI/PSI, dan evidence contract yang memisahkan Candidate dari Validated. WebUI membaca status yang dikeluarkan daemon, bukan mengasumsikan kemampuan.

PR #21–22 — Runtime hardening & per-thread cgroup control · MERGED

Memperkuat config, thermal floor, serta service lifecycle. Cgroup v2 thread migration memakai journal identitas TGID/TID, memeriksa threaded hierarchy, menulis hanya ke cgroup.threads, lalu membaca ulang hasil; pemulihan menjaga perubahan OEM.

PR #26–28 — Frame bridge, telemetry correction & autonomous lifecycle · MERGED

Menambahkan kontrak frame/touch event, memperbaiki interpretasi snapshot interval KGSL tanpa mengklaim actuation Qualcomm, serta mengaktifkan startup observation gate dan live daemon status IPC. Event bridge dasar bukan bukti SurfaceFlinger FrameTimeline tersedia.

PR #29 — Native input & foreground render-thread actuators · DRAFT / NOT MERGED

Menambahkan evdev touchscreen source dengan ioctl filtering dan hotplug recovery, RenderBooster touch burst, foreground process/thread resolver, serta per-thread cgroup v2 placement dengan identity/readback/rollback. Host CTest dan ASan/UBSan mencakup 50 siklus FD-count regression; CI hijau tetap belum menggantikan validasi runtime pada perangkat Android.

Buka PR #29 ↗ · CI Run #1362 ↗

Garis pemisah utama sejak PR #7: kemampuan menulis bukan otoritas. Setiap actuator harus membuktikan capability, semantik, batas, ownership, readback, dan rollback. Fitur observation-only atau belum tervalidasi tidak boleh dipasarkan sebagai actuator yang selesai.
